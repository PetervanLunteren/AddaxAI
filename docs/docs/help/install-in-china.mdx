# Install in mainland China

The first launch downloads the AI models and the software they run in. In mainland China those downloads fail or stall, because the servers they come from are blocked or very slow. The fix is to use mirrors: copies of the same files on Chinese servers.

You need AddaxAI 7.0.13 or newer.

<Tabs groupId="os" queryString="os">
  <TabItem value="windows" label="Windows" default>

## Point the app to the mirrors

1. Open the Start menu and search for "environment variables".
2. Open Edit the system environment variables, then click Environment Variables.
3. Under User variables, click New and add these three, one by one:

   | Name | Value |
   |---|---|
   | `ADDAXAI_HF_ENDPOINT` | `https://hf-mirror.com` |
   | `ADDAXAI_HF_HUB_DISABLE_XET` | `1` |
   | `ADDAXAI_PYTORCH_INDEX_URL` | `https://mirror.nju.edu.cn/pytorch/whl` |

4. Click OK to close the windows.

## Point the installer to the mirrors

1. Open Notepad and paste this:

   ```ini
   [global]
   index-url = https://mirrors.aliyun.com/pypi/simple/
   ```

2. Save it as `pip.ini` in the folder `C:\Users\<your user name>\AppData\Roaming\pip`. Create the `pip` folder if it is not there.

## Restart

Restart your computer, open AddaxAI, and run the setup again. It continues where it stopped.

  <TabItem value="macos" label="macOS">

## Point the app to the mirrors

Paste this in Terminal. It sets the mirror at every login, so it keeps working after a restart and for models you install later:

```bash
cat > ~/Library/LaunchAgents/com.addaxai.mirrors.plist << 'EOF'
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>Label</key><string>com.addaxai.mirrors</string>
  <key>ProgramArguments</key>
  <array>
    <string>/bin/sh</string>
    <string>-c</string>
    <string>launchctl setenv ADDAXAI_HF_ENDPOINT https://hf-mirror.com; launchctl setenv ADDAXAI_HF_HUB_DISABLE_XET 1; launchctl setenv ADDAXAI_PYTORCH_INDEX_URL https://mirror.nju.edu.cn/pytorch/whl</string>
  </array>
  <key>RunAtLoad</key><true/>
</dict>
</plist>
EOF
launchctl load ~/Library/LaunchAgents/com.addaxai.mirrors.plist
```

To stop using the mirror later, delete that file and restart your Mac.

## Point the installer to the mirrors

Run these lines in the same Terminal:

```bash
mkdir -p ~/.config/pip
cat > ~/.config/pip/pip.conf << 'EOF'
[global]
index-url = https://mirrors.aliyun.com/pypi/simple/
EOF
```

## Run the setup

Open AddaxAI and run the setup again. It continues where it stopped.

## Point the installer to the mirrors

Open a terminal and run:

```bash
mkdir -p ~/.config/pip
cat > ~/.config/pip/pip.conf << 'EOF'
[global]
index-url = https://mirrors.aliyun.com/pypi/simple/
```

## Point the app to the mirrors

Paste this in the same terminal, then log out and in. It sets the mirror for every session, so it keeps working after a restart and for models you install later:

```bash
mkdir -p ~/.config/environment.d
cat > ~/.config/environment.d/addaxai-mirrors.conf << 'EOF'
ADDAXAI_HF_ENDPOINT=https://hf-mirror.com
ADDAXAI_HF_HUB_DISABLE_XET=1
ADDAXAI_PYTORCH_INDEX_URL=https://mirror.nju.edu.cn/pytorch/whl
EOF
```

To stop using the mirror later, delete that file and log out and in.

The mirrors are free services from universities and volunteers. They can move or go offline. If one stops working, [let me know](mailto:peter@addaxdatascience.com).

## If it still does not work

The steps above are enough for most people. Only if setup still fails, open the part below that matches your problem.

<FaqItem
  id="setup-sits-at-the-same-percentage"
  q="Setup sits at the same percentage for a long time"
>

On Windows one file is about 3.4 GB. The percentage stays the same while it arrives, but the megabytes below it keep counting up. As long as that number grows, setup is working. On a slow line this one file can take an hour or more.

Do not close and restart the setup. A part-finished file is not kept, so every restart begins that 3.4 GB again.

</FaqItem>

<FaqItem id="a-model-download-keeps-failing" q="A model download keeps failing">

You can fetch the model files yourself. Open the model's page on the mirror, download every file, and put them in the model's folder under `C:\Users\<your user name>\AddaxAI\models` (on macOS and Linux: `~/AddaxAI/models`). Keep the file names as they are.

| Model | Files | Folder |
|---|---|---|
| MegaDetector v5A | [hf-mirror.com/Addax-Data-Science/MD5A-0-0](https://hf-mirror.com/Addax-Data-Science/MD5A-0-0/tree/main) | `models\det\MD5A-0-0` |
| DINOv2 ViT-S/14 | [hf-mirror.com/Addax-Data-Science/DINOV2-VITS14](https://hf-mirror.com/Addax-Data-Science/DINOV2-VITS14/tree/main) | `models\emb\DINOV2-VITS14` |
| SpeciesNet 4.0.2a | [hf-mirror.com/Addax-Data-Science/SPECIESNET-v4-0-2-A](https://hf-mirror.com/Addax-Data-Science/SPECIESNET-v4-0-2-A/tree/main) | `models\cls\SPECIESNET-v4-0-2-A` |

Other species models work the same way. Their folder is `models\cls\<model id>`, with the id as shown in the [model zoo](../reference/model-zoo.mdx).

</FaqItem>
