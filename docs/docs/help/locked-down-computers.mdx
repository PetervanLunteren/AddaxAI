# Install on locked-down computers

Some organizations only allow programs to run from specific folders. Government and university computers often work this way. The app then installs fine, but setup fails with an error like "This program is blocked by group policy". The fix is to put both the app and its data folder in allowed locations.

You need AddaxAI 7.0.8 or newer.

## Why it fails

There are two parts:

- The app itself. It installs to the location you pick in the installer.
- The data folder. It holds your database, the AI models, and the software the models run in. By default it is `C:\Users\<your user name>\AddaxAI` (on macOS and Linux: `~/AddaxAI`).

The AI runs from the data folder. When the policy blocks programs in user folders, that is the part that fails, even when the app opens fine.

The easiest solution is to ask your IT department to allow programs under the default data folder, `C:\Users\<your user name>\AddaxAI`. If they do, you are done and can skip the rest of this page. If they don't, follow the fix below.

## The fix

1. Install the app into an allowed folder. The installer lets you pick the location. To install with a script, see [silent install](silent-install.mdx).
2. Set the environment variable `ADDAXAI_USER_DATA_DIR` to an absolute path in an allowed location, for example `C:\Apps\AddaxAI-data`. The data folder then lives there instead of in the user folder.

<Tabs groupId="os" queryString="os">
  <TabItem value="windows" label="Windows" default>

Set the variable machine wide so it applies to every user:

1. Open Start and search for "environment variables".
2. Choose "Edit the system environment variables", then "Environment variables".
3. Under "System variables", add `ADDAXAI_USER_DATA_DIR` with the path as the value.
4. Start the app and run the setup.

  </TabItem>
  <TabItem value="macos" label="macOS">

A plain `export` in the shell does not reach apps started from the Dock, so set the variable with a login agent. Paste this in Terminal, with your folder on the `<string>` line:

```bash
cat > ~/Library/LaunchAgents/com.addaxai.data-folder.plist << 'EOF'
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>Label</key><string>com.addaxai.data-folder</string>
  <key>ProgramArguments</key>
  <array>
    <string>/bin/launchctl</string>
    <string>setenv</string>
    <string>ADDAXAI_USER_DATA_DIR</string>
    <string>/path/to/folder</string>
  </array>
  <key>RunAtLoad</key><true/>
</dict>
</plist>
EOF
launchctl load ~/Library/LaunchAgents/com.addaxai.data-folder.plist
```

This survives restarts. Then start the app and run the setup.

  </TabItem>
  <TabItem value="linux" label="Linux">

A plain `export` in the shell does not reach apps started from a desktop icon, so set the variable for the whole session. Paste this in a terminal, then log out and in:

```bash
mkdir -p ~/.config/environment.d
echo 'ADDAXAI_USER_DATA_DIR=/path/to/folder' > ~/.config/environment.d/addaxai.conf
```

This survives restarts. Then start the app and run the setup.

  </TabItem>
</Tabs>

## Things to know

- The folder must be writable by the user account that runs the app. If it is not, the app shows an error at startup that names the folder.
- The variable does not move anything. The app starts fresh in the new folder: an empty database, and setup downloads the models again. To keep earlier work, close the app and move the old folder's contents into the new folder first.
- Setup needs to reach `huggingface.co` and `github.com`. On networks that block those, ask IT to allow them, or see [install in mainland China](install-in-china.mdx) for mirrors.
